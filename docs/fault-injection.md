# 论文故障与进度查看

打开 http://127.0.0.1:14000/inject ，选择节点与故障，点击“注入故障并查看进度”。注入后直接打开任务详情，每 2 秒读取已存储事件。自动处置暂停时需要手动运行诊断，或重新开启自动处置。

依据本项目 `FedHELM-cn.pdf` 第 15 页 §6.1，论文包含 CPU 饱和、内存泄漏、线程池耗尽、磁盘写满、数据库连接池耗尽、网络延迟、分组丢失、依赖超时、服务崩溃、配置错误十类。页面列出全部十类及支持状态。

| 当前支持项 | 实际注入机制 | 恢复动作 |
|---|---|---|
| 服务崩溃实验 | 停止本项目独立业务子进程，实际请求不可达；不是模拟任意崩溃根因 | 重新启动业务 |
| 配置错误 | 修改本端业务配置文件，订单请求返回 503 | 恢复配置 |
| 数据库连接池耗尽 | 持有 SQLite 的四个连接，订单请求等待连接超时 | 释放连接 |
| 线程池耗尽（新增） | 占住两个真实工作线程，业务任务等待工作线程超时，返回 503 | 释放工作线程 |
| 依赖超时（新增） | 本机独立 HTTP 测试依赖延迟 250 ms，订单服务的依赖请求超时，返回 503 | 恢复依赖响应并排空积压 |

线程池和依赖均在本项目业务进程内，依赖只监听回环地址；固定两个工作线程，不运行 CPU/内存压力测试，不写满电脑磁盘，不修改宿主机网络。其余五类暂不可选，等待具备资源限额、独立卷和网络命名空间的环境。当前仍为 Windows 同机独立进程测试床；K8s 适配器代码已支持新增接口，但尚未完成集群部署与实测。

## 诊断与训练边界

原三类故障及正常状态继续使用四分类 `torch-mlp-v1`，实际端侧训练、增量上传、聚合与下发保持可用。新增两类由端侧显式日志规则识别，诊断记录使用 `explicit-fault-rules-v1`，证据说明分值不是神经模型概率。新增类别尚未纳入四分类训练集，不宣称神经模型已经学习这两类。大小语言模型仍为占位接口。

## 进度与时间

七个里程碑是：故障出现 → 观测采集 → 端侧诊断 → 选择模型 → 处置方案 → 执行修复 → 恢复验证。进度按已有记录计算，不按时间自动增长。注入接口返回成功只代表第一个里程碑，不代表恢复。

- 显示开始时间、最近事件、各阶段时间、距任务开始和上一事件的耗时。时间按浏览器本地时区显示，精确到毫秒；数据库保存 ISO 时间。
- 新记录包含观测、诊断、方案、执行回执及验证样本；展开“查看输入输出与验证证据”查看详情。历史旧记录缺少独立执行返回时间时会标注。
- 恢复验证通过才完成最后一个里程碑；案例入库单独显示，未入库不冒充已入库。
- 故障失败会显示未完成阶段；手动恢复或重新注入会记录原任务人工终止或被新实验替代。
- “等待后续事件”仅表示没有后续记录，不保证后台仍在执行。服务重启、日志传输失败或人工暂停均可能导致等待。
- 当前是三次短时 HTTP 观测，每次包含三次业务请求；不是论文的五分钟 SLO 验证窗口。

事件保存在边缘 `runtime/training/edge/history.sqlite`，任务列表、操作日志仍可追溯。接口为 `GET /ui/fault-catalog`、`GET /ui/task/{task_id}`，中文接口说明见 `/docs`。

## 验证

`python -m scripts.verify_fault_extensions` 在 B 端顺序真实注入两类新增故障，检查注入观测为 503、自动恢复样本为 200、规则诊断来源、七个里程碑及案例入库，报告在 `runtime/fault-extension-verification.json`。该脚本会短时启用自动处置并在结束时还原开关，运行前请停止其他手动实验。

完整四分类训练与联邦链路通过 `scripts.verify_real` 验证，报告在 `runtime/fault-extension-training-verification.json`。
