# 论文与原型实现核对

核对依据：FedHELM-cn.pdf 第 3–5 节及 §6.1；当前代码静态检查。本文不是新的运行验收报告。

## 总体结论

当前是可运行的简化闭环原型，并未完整实现论文关键算法。真实故障注入、HTTP 采样和真实梯度训练，不等于完成论文算法复现，也不能据此证明泛化诊断能力。

## 模块与算法

| 论文内容 | 当前实现 | 主要差距 |
|---|---|---|
| 多源故障事件：日志、指标、调用链、告警、上下文 | real_workload 采集实际订单请求、错误日志、连接池占用，history 保存指标 | 没有完整的多源采集、时序窗口、调用链；不是论文的 12 项指标 × 20 时点 |
| 端侧编码器与分类头 | learning.py 实际 PyTorch MLP，8 输入、12 隐层、4 输出，160 参数 | 不是论文 6 层 Transformer / 22.6M 参数；嵌入是手工遥测特征，而非学习得到的故障表示 |
| 算法 1：资源感知模式选择 | A/B/C 可行性、置信度阈值、内存与 RTT 条件分支 | 缺时延/能耗/通信/精度加权代价最小化、EWMA、案例难度评分、记忆冲突升级、边缘队列代价 |
| Local / Edge 语言模型 | 本地、边缘 HTTP 占位接口与结构化动作模板 | 尚无真实 SLM/LLM 推理，符合暂用占位服务的约定 |
| 算法 2：故障感知联邦优化 | 真实端侧训练、验证 F1、增量上传；样本量 × 多样性/质量/稳定性评分聚合；版本下发与持久化 | 缺探针一致率、质量和稳定性 EWMA、论文冷启动策略、8 位量化与 Top-50% 稀疏化；服务为自定义 HTTP，而非 Flower |
| 联邦故障记忆 | SQLite 案例、余弦相似度筛选、成功动作复用、案例同步 | 缺 FAISS、分类概率与记忆投票 0.65/0.35 融合、完整摘要与频次策略 |
| 资源控制器 | 接收端侧资源状态并参与模式选择 | CPU、可用内存、带宽、RTT 主要是手工策略值，非实际持续采样 |
| 自动故障管理 | 轮询业务、异常触发、模型选择、执行、恢复验证、重试上限、记录 | 巡检触发主要依赖健康与错误率，缺仅时延异常等触发；恢复只验证短时 HTTP，不是论文五分钟 SLO |
| 边端部署 | 同一电脑的独立服务进程，各端独立模型和数据目录 | K8s 配置/适配器存在，但集群尚未部署验证 |

## 是否把注入答案传给了诊断

当前 `/run` 仅接收事件编号及可选强制路径，然后重新调用业务 `/observe`。诊断函数接收观测与模型，没有接收故障注入的类型。调度器也可在没有注入记录时根据坏的业务观测发起处置。

`dashboard.truth` 保存实验标签，用于处置之后核对根因、确认案例。没有实验标签的故障仍可诊断和修复，但当前不能通过这条自动核验路径作为已确认根因的案例入库。这是原型限制。

然而，现有诊断证据过于简单：四分类模型将三个固定错误短语转换成特征；新增线程池耗尽和依赖超时由固定日志规则直接识别，规则分值设置为 1.0。这不是直接读取注入标签，但容易依赖测试夹具特征，不能当作真实场景诊断能力。训练与验证事件编号不同，也不足以证明能泛化到其他业务和未知故障。

## 数据接口的实际含义

| 服务 / 接口 | 用途 | 当前限制 |
|---|---|---|
| 测试业务 `GET /metrics` | 连接池、工作线程容量/占用、测试依赖信息 | 自定义 JSON，不是 Prometheus 标准导出器；控制信息不得直接充当诊断答案 |
| 业务控制器 `GET /observe?event_id=...` | 发起三次真实订单请求，产生观测 | 单次摘要，没有完整时序窗口 |
| 边缘 `GET /ui/history` | 查询保存的指标、任务与事件 | 是查询接口，不是通用外部遥测接入接口 |
| 端侧 `PUT /resources`，边缘 `POST /resources` | 更新调度策略资源状态 | 大部分值目前人为设置 |
| 端侧 `POST /collect` | 实验中按类注入，保存带标签的训练/验证样本 | 这是训练数据制作，不是持续监控采集器 |
| 端侧 `POST /run` | 对当前实际观测执行诊断与处置 | 不接收注入故障类别 |

## 下一步应有的数据流

测试业务持续运行 → 每端独立采集器采样指标、日志和调用链 → 保存时间窗口 → 异常检测生成告警 → 轻量模型给出候选根因与置信度 → 记忆融合和算法 1 选择推理模式 → 生成并执行动作 → 同一批指标持续验证恢复 → 记录与案例审核。

注入器只改变被测业务；评估器另存标签，用于事后评分。推理输入应明确排除注入类型、控制开关和目标恢复动作。训练阶段使用标签正常，在线诊断不可使用标签。

优先补：真实资源与业务指标采集、窗口化异常检测（包含单纯延迟异常）、诊断与实验标签的接口隔离及负向测试、去除单一固定日志的答案捷径。之后补算法 1、算法 2 和记忆融合。指标异常用于发现问题，根因仍需结合日志和调用链：高时延不能唯一确定是线程池、数据库、CPU 还是下游依赖。
