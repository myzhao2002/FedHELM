# FedHELM：论文与当前 K8s 系统机制核对

核对日期：2026-09-10。依据：项目 `FedHELM-cn.pdf` 第3—7节、当前源代码、K8s边侧容器内查询的端侧health和模型API配置。本文是机制审查，不是全量实验复现报告。本次未修改运行策略、触发训练或调用付费模型。此前历史审查中的“尚无K8s”“只有MLP”等描述已经过时。

## 结论

当前是论文框架的缩小版工程原型：已部署真实K8s、16个逻辑端，具有采集、时序编码、三模式调度、约束执行、反馈、记忆、压缩更新和贡献度聚合。但自动学习轮次尚未闭合，资源代价、数据本地化、恢复判定等存在实质差异，不能只补数据就视为算法完全一致。

## 1. 论文怎么训练更新

§3.2和算法2描述两个相互关联的循环：

- 单故障循环：观测→诊断→方案→自动执行→SLO反馈→验证经验。
- 联邦轮次：参与端本地训练2个epoch→上传压缩增量、标签直方图及验证知识条目→边缘计算多样性D、质量Q、稳定性S→按样本量×贡献度聚合→更新记忆→下发新模型和高频记忆摘要。

联邦训练对象是故障编码器及分类头；SLM/LLM权重冻结。实验运行100轮，ALFA实验80轮。论文未明确工程触发规则，如定时周期、新样本阈值、忙时延迟、掉线超时和重试规则。不能把“每5分钟训练”当论文原文，也不能把效果门槛/自动回滚说成论文已有要求。它们可以作为工程补充。

当前有单故障自动调度，没有联邦轮次调度器；本地训练手动发起，随后自动上传；聚合手动发起；全端同步手动发起，故障处理每次尝试前也会拉取模型。尚未把在线反馈自动整理成合格训练记录。

## 3. 本次K8s即时状态

只读查询显示：a01—c01共12端为temporal-transformer-v2，c02—c05四端仍为mock-bias-v1初始化模型；全部v0，累计训练样本均0；全部恢复观察设置3秒；边侧大小模型角色均disabled且无密钥。

原因之一是Agent启动只读本地已有模型，未统一执行启动同步；自动处置只会在异常尝试前同步。故Pod Ready不是模型 Ready。此状态会随用户操作变化，本报告不代表未来状态。

## 4. 论文原文本身需要澄清的地方

- 未给出联邦轮次启动频率、反馈如何补全根因标签、掉线处理等工程细节。
- 稳定性声明归一化至0—1，但余弦公式可为负；实现需要约定映射。
- 冷启动写qi与niDi成比例，聚合又乘ni，意味着样本量近似平方加权；当前实现按这个字面结构，不应不加说明地当作普通样本量加权。
- 探针一处写边缘下发，另写服务器评估；现实现选择服务器评估分类头。旧嵌入随编码器变化的兼容性未充分说明。
- 固定10类模型与后续新增TLS类型的分类头扩展/开放集识别协议没有给全。
- 本地化约束与Edge上传关键日志指标摘要应明确边界，不能解释为任何观测内容都不离端。

## 5. 按用户“流程贴论文，效果次要”的优先级

1. 初始化就绪：所有端同步正确编码器、接好API，并在页面区分服务就绪和模型就绪。
2. 联邦轮次调度：参与集合、训练→上传→聚合→同步、超时重试、轮次日志；低并发和资源上限可保留，但明确属于本机仿真选择。
3. 反馈数据闭环：成功/失败、根因确认、训练样本准入、事件分区、紧凑知识条目；注入真值只用于标签与评分，不能进入在线诊断输入。
4. 修正恢复语义：事件/处置起点、5分钟截止、恢复稳定窗口、人工干预记录。
5. 修正代价输入：容器资源余量、API版Local真实网络开销、准确率与恢复率分开，先验和权重可配置。
6. 统一训练协议、数据时间尺度和数据划分，再完善压缩二进制格式、记忆版本/摘要及缺少故障类型。
7. 若只演示流程，缩小模型、API替代、本机K8s、小业务可以保留；要复现实验数值，另补论文规模、业务、数据、网络、基线和统计实验。

不应把“加训练数据”作为所有差异的解法：它可能改善分类效果，但补不了轮次调度、反馈样本准入、动作序列、网络注入和SLO判定。
