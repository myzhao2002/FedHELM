# 自动联邦训练与反馈闭环

本次更新适用于16端K8s版。控制台： http://127.0.0.1:16000/lab?ui=nav5 。

## 如何操作

在“训练与调试”顶部“自动联邦轮次”中，可以启用/暂停自动运行、设置轮间隔和累计轮次上限，或点击“执行/恢复一轮”。当前初始策略为最多3轮、轮间隔900秒、训练并发1。上限是本控制器累计完成轮数；达到上限后不再自动开新轮，增大上限可继续。手动执行一轮不受自动上限约束。暂停自动运行会在端侧步骤之间停下，正在执行的单端请求会完成；手动发起的一轮会继续完成。

只使用各端已经激活的训练数据集，不会为了训练自动注入故障。缺训练/验证数据、业务异常、节点不可达或主机可用内存不足512MB时，面板显示等待原因。失败保留持久化更新，下一次恢复跳过已上传节点；聚合后下发失败则继续同步，不重新聚合。

每轮：各端同步同一全局版本 → 串行真实PyTorch训练（2epoch、batch32、AdamW 0.0005） → Top50%/INT8数值压缩上传 → 16端齐备后贡献度聚合 → 逐端同步模型与记忆并确认版本 → 记录完成时间。隔轮等待从上一轮完成时开始计算。目前仍使用JSON压缩协议和固定16端参与。

面板显示每端阶段及加载版本。当前轮次链接进入任务日志；“模型与传输”“操作日志”也保留各服务记录。自动处置与自动训练是两个独立开关，不会互相代替。训练与处置通过共享操作锁错开执行，训练间释放锁；它并不是严格实时调度器。

## 启动与模型就绪

端侧采集线程启动后先同步全局模型与记忆，失败则重试。首次模型是未训练v0，需要训练才能积累参数更新。Pod Ready表示服务就绪，仍应检查模型版本和训练样本数。

大小模型配置已从原进程版迁至K8s，密钥挂载于边侧 `/secrets/bailian-api.key`。本次将每日调用上限收紧为每角色5次，可在API配置页调整。训练不调用语言模型API。删除Windows密钥文件不会删除K8s Secret；停止使用时禁用API并删除集群Secret，必要时在服务商撤销密钥。

## 恢复判定

默认在执行动作后300秒内等待恢复。允许初期异常，连续健康至少2秒且最近至少3个观测健康才判恢复；健康条件为错误率≤5%、请求时延≤500ms。健康后可提前结束，不必等待整整5分钟。

运行开始时读取测试业务的干预修订号；验证期间若通过注入接口再次注入/手动恢复，修订号变化，不能记为无人工干预成功。进程外直接修改文件等操作目前不在这个修订号检测范围。当前截止计时从动作执行返回起算，论文未详述计时边界；如需以故障发生为起点，仍要进一步统一事件时间。

## 已确认反馈进入本地训练

端侧保留本次诊断前的数值窗口及恢复结果。操作员在成功任务详情确认根因并收录案例后，边侧向原端发送事件编号和确认标签；端侧必须已有该事件且恢复成功才能准入。

同一事件用哈希固定划分：70%训练、10%验证、20%测试（总体比例，小样本不保证恰好匹配）；重复确认幂等、不同标签拒绝覆盖。训练会将已确认事件与已激活数据集合并，训练函数只使用train和validation，test不参与优化。原数值窗口不为此确认动作重新上传。记录存放在各端 `/data/agent/feedback-events/`。

此处仍需要人工确认根因，不会把模型猜测直接当标签；尚未自动对接独立实验站的真值评估，也未把失败案例自动转换为训练记录。没有激活基础数据集时，单独反馈语料目前不会启动训练。案例已入库但端侧确认失败时，接口返回待重试，可再次确认同一案例。

## 本次仍保留的差异

模型仍为32维紧凑Transformer；A/B/C容器配额尚未分档；大小模型采用API。训练轮次没有自动效果门槛或回滚，也不承诺每轮准确率提高。记忆库仍是SQLite、案例仍含反馈样本，未改为每轮最多20条紧凑知识协议。多源编码、FAISS/Flower、二进制增量、五类额外故障、ALFA及论文统计实验仍未补齐。

自动轮次不是无人管理的无限训练：默认预算到3轮即停，后续根据需要提高上限。各端新生成的数据仅用于仿真流程验证，不代表论文数据集或真实实验效果。

Pod或Docker重启后网页打不开时，可双击项目根目录`open-k8s16.cmd`恢复两个端口转发；它不会关闭其他占用端口的程序，连接错误看runtime下forward日志。Docker重启后若kind节点处于停止状态，先执行`docker start fedhelm16-control-plane fedhelm16-worker`，再等待节点Ready并恢复端口转发。旧Windows进程版已停止以释放内存。
