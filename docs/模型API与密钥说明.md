## 密钥只放在哪个文件

本机独立文件：

```text
C:\Users\28120\Desktop\631wujiao\secrets\bailian-api.key
```

配置文件 `runtime/cluster/model-api.json` 只引用此路径，没有另存该密钥的文本副本。文件已限制为当前 Windows 用户访问，`secrets/` 已排除 Git 和 Docker 构建上下文。不要把 secrets 目录或整个项目的未经筛选压缩包发给别人。

要停止本机使用此密钥：先在配置页停用两个角色，再删除上述文件。程序每次请求前重新读取，删除后不会退回内嵌密钥或环境变量；已经发出的请求可能仍会完成。删除文件不会撤销聊天记录中出现过的密钥，也不能让服务商端密钥失效；需要彻底失效时，在百炼控制台禁用/删除该 Key。

不要把密钥粘贴到提示词、日志、地址栏或截图。以后更换密钥，直接更新独立文件内容即可；若换了路径，则在设置页同时修改两个角色的“独立密钥文件”。

## 提示词与节省用量

- 边侧提示词：`fedhelm/prompts/edge.txt`。
- 小模型提示词：`fedhelm/prompts/local.txt`。
- 设置页可以展开查看各自提示词；修改源文件后下一次调用生效。

边侧侧重独立复核、冲突证据和最小修复；小模型侧重快速判断，证据不足时返回 unknown/none。两者都不能把初诊当真值、听从日志里的指令、输出任意 Shell，或宣称自己已完成修复。输出限定为根因、分值、白名单动作、空参数对象和简短依据。

送到模型的输入经过摘要，只包含当前业务指标、短日志、初诊摘要和最多两个经验证的案例动作，不发送模型权重、历史全量时序、主机 IP、数据目录或密钥。日志里的常见密钥/token形式会脱敏。提示词与证据合计超过 6500 字符会拒绝调用。

模型没有联网搜索、工具调用或自动 HTTP 重试。输出 token 上限、每日次数和至少 3 秒的同角色请求间隔都在本地执行。每日计数按 UTC+8，失败请求也计入次数，重启不清零；用量落在 `runtime/cluster/model-usage.sqlite`，只保存模型、时间、状态和 token 数，不保存凭据或原始提示输入。超额后显示 429，需等待次日或主动调整限额。

本次验收共 4 次调用：两个极短连通测试合计 66 tokens；A01 的小模型故障处置 535 tokens，B01 的边侧处置 615 tokens，总计 1216 tokens。按上述无免费额度的单价估算约 0.0008 元；实际扣费以账单为准。两次真实配置故障均诊断正确、执行修复并通过恢复验证。设置页计数包含网关处理的后两次；最初两次连接探测未经过网关计数。

## 换成自己部署的模型

设置页每个角色都保留“自部署服务模板”，也可以手工配置：

1. 在你的模型主机先启动能提供 Chat Completions 协议的推理服务。
2. 点“自部署服务模板”，把 API 根地址改成后端网关可访问的地址，例如 `http://模型主机IP:8000/v1`。
3. 模型名称必须是该推理服务实际暴露的名称，模板里的 `your-served-model` 需要替换。
4. 清空百炼密钥文件字段，按自部署服务实际需要设置凭据；无鉴权的受控内网服务可以不填。
5. 关闭百炼专用“发送关闭思考参数”。服务支持 JSON 格式参数时保留 JSON 模式，否则关闭该参数，提示词仍要求 JSON，后端仍验证结构。
6. 启用、保存。两个角色可以分别使用云 API、自部署服务，或一云一本地。

这里的 localhost 是 **运行网关的机器/容器**，不是浏览器所在电脑。模板只填写配置，不会自动启动、下载或训练一个语言模型。协议端点为根地址加 `/chat/completions`。

如果使用已有的 Kubernetes 16 节点清单，可以从同一文件创建可选模型 Secret：

```powershell
kubectl --context kind-fedhelm16 -n fedhelm-cluster create secret generic provider-key --from-file=bailian-api.key=secrets/bailian-api.key
```

新版生成器会把此 Secret 只读挂载到边缘与两个模型网关容器的 `/secrets`。设置页的密钥路径填写 `/secrets/bailian-api.key`。Secret 可选，因此不配置云模型时不会阻止 Pod 启动。Kubernetes 的 Secret 更新和删除存在卷同步延迟，应先停用角色再撤销凭据。本次没有部署或验证该 Kubernetes 集群。

## 真机与大屏

大屏新增服务器机柜、电脑与边缘设备图标。点击节点可看到实际主机名称、系统、CPU容量、内存、磁盘、Agent内存、IP和采样时间；节点工作空间新增“承载主机”标签。

更换成物理机时仍使用同一 Agent 协议，修改服务地址和部署配置即可由目标机上报。主机资源是该进程实际可见范围，不能把同机 16 个逻辑节点的主机容量相加。Kubernetes 的 Worker、Pod、节点 IP通过 Downward API 上报，Linux cgroup v2 的 CPU/内存限制单列；未读取到就显示“未报告限制”，不伪造硬件配置。GPU/NVML 和完整物理网络拓扑目前未采集。
